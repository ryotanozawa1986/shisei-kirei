# シセイキレイ 開発進行表

## 現在の方針

正面カメラ・座位・上半身のみで実装しやすい姿勢改善体験をMVPとする。
初期版では医療的な診断ではなく、カメラ上で確認できる姿勢変化をスコア化して「その場で良くなる体験」を提供する。
初期リリースはWebアプリ / PWAに集中し、iOS / Androidアプリ化はWeb版で体験検証ができた後に検討する。
履歴は再来につなげる主要導線としてMVPに含め、localStorage保存の永続性は保証しない。
本番環境はCloudflare Pagesを利用し、スマホ実機確認用のHTTPS環境は開発中に適切な方法を選定する。

## ページ構成・ユーザーフロー

### ページ構成

- `/`
  - トップ兼スタート画面
  - 初回ユーザー向けにサービス説明、カメラ利用説明、測定開始ボタンを表示する
  - 履歴がある場合は前回スコア、前回からの変化、再測定導線を表示する

- `/measure`
  - カメラセットアップ、初回測定、改善アクション、再測定を同一ページ内のステップ管理で進める
  - カメラ権限、MediaPipe初期化、測定状態をページ遷移で分断しない

- `/result`
  - Before / After結果を表示する
  - 総合スコア、改善点、レーダーチャート、今回の保存結果を表示する
  - 「もう一度測る」「履歴を見る」への導線を用意する

- `/history`
  - 履歴グラフを表示する
  - 総合スコア推移をメインにし、各項目スコアはタブまたは切り替えで表示する
  - 再来を促すため、前回からの変化を見せる

- `/privacy`
  - プライバシーポリシー

- `/terms`
  - 利用規約

### ユーザーフロー

- 初回：`/` → `/measure` → `/result` → `/history`
- 再来：`/` で前回スコア・変化を確認 → `/measure`
- 測定体験：カメラセットアップ → 初回測定 → 結果表示 → 改善アクション → 再測定 → Before / After表示 → 履歴保存

## SEO方針

トップページは測定開始だけでなく、姿勢に関する悩みを拾うSEO入口として設計する。
売り込み感の強いLPにはせず、ユーザーの悩みに答える解説ページの中に自然な姿勢チェック導線を置く。

### 狙いたい検索ワード

- ストレートネック
- 姿勢
- 腰が痛い
- 首が痛い
- 姿勢 悪い
- 姿勢 改善
- 猫背

### トップページに入れるコンテンツ

- 悩み訴求（首・腰・姿勢の違和感）
- 姿勢チェックを始める自然な導線
- ストレートネックとは
- 姿勢が悪くなる原因
- これをやると姿勢が悪くなりやすい行動
- 首が痛い・腰が痛いときに姿勢で見直したいポイント
- 猫背・ストレートネック・肩の高さの左右差など、チェックできる項目の説明
- よくある質問（Q&A）
- カメラ映像を保存しないこと、医療診断ではないことの説明

### SEO実装方針

- トップページはスマホ縦画面優先のまま、検索流入向けの本文量も確保する
- 見出し構造は `h1`、`h2`、`h3` を適切に使う
- Q&Aは構造化データを追加できる形で実装する
- 症状・悩み系キーワードは断定的な医療表現を避け、「可能性」「傾向」「セルフチェック」という表現にする
- CTAを過剰に繰り返さず、本文中とページ上部・下部に自然に配置する
- 煽り表現や強いビフォーアフター訴求は避け、信頼感のあるセルフチェックサービスとして見せる
- 将来的には `/articles/straight-neck` などの記事ページを追加し、トップは姿勢チェックと記事へのハブにする

## リスク・注意点

- `反り腰` は正面上半身のみでは判定根拠が弱いため、初期MVPでは対象外にする。
- カメラ映像・画像・動画は保存しない方針を維持する。
- スコアは医学的評価ではなく、画面内での姿勢変化の目安として扱う。
- MediaPipeの検出精度は端末・明るさ・服装・背景に影響されるため、測定不可時の案内を丁寧に作る。
- iOS Safariではカメラ・PWA・パフォーマンスの制約が出やすいため、早めに実機確認する。
- 有料機能や長期履歴を提供する場合は、アカウント・サーバー保存・課金状態管理が必要になる。
- 広告収入は主軸にせず、個人向け有料会員と接骨院・整体連携を収益化の本命として検討する。
